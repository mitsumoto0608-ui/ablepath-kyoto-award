## 3-A 残存幅scenarioビルダー（scenarioを作る道具。被害を予言する道具ではない）

目的：地震scenario（弱/中/強）の閉塞集合の**導出を較正済み分布に接続**する。横屋2024（益城の当該検証で最良設定でも最大一致78.8%＝不一致が残る一例。単純な誤判定率と読み替えない）が「個別道路の被害を断定しない」理由。

**層の分離（v2.1改訂・重要）**：ビルダーは**profile非依存の物理値**を第一級出力とし、profile別の通行可否は判定層が決める。混ぜない。

```text
入力: edge毎 W_clear（実効幅＝最狭点実測。Coppola&Marshall 2021: 静的障害物だけで
      平均幅1.4→1.1m・ADA3ft適合78→51%——公称幅を信じない）
      沿道建物 h（PLATEAU LOD1/2）、構造・年代クラス、左右どちら側か
需要: scenario s の指定倒壊クラスに入る沿道建物 b について**3段階を分離**——
      ① damage_state：倒壊するか（scenario指定。個別予測はしない）
      ② debris_present：道路側へ瓦礫が出るか。M7コアではbool値を明示入力する。
         Moya Eq.7 P[D=0|h,collapse]=1.5e^(−0.43h) からscenario別の建物集合を決定値化する規則は
         **別タスクの未決事項**であり、M7コア内で閾値を発明しない。
         `DAMAGED`かつ`debris_present=true`は矛盾入力として停止する
      ③ debris_extent：D(b) = MOYA_DEBRIS_SLOPE·h_b + MOYA_DEBRIS_INTERCEPT [m]
         （=0.31h+1.10。Moya Eq.2・益城町木造建物・A2・TRANSFER=ADAPT）
         Eq.2/3はD>0回帰部分標本n=738。full sample母数はここで断定せずRESEARCH_LEDGER参照。
         感度variantは +1σ（σ=1.11、同じD>0回帰部分標本n=738）。呼称は mean_case / sensitivity_high_case
      ④ **後退距離**：歩行空間への実侵入 I_side = max(D − S_side, 0)（S=建物から歩行空間までの後退。
         瓦礫3mが後退2mの建物から全部歩行空間に入るわけではない）
      ⑤ **複数建物の集約**：建物の影響投影区間でedgeを分割するgeometry処理は別タスク。
         M7 core v0.3へ渡す各小区間は左右それぞれ0件または1件のeffective buildingに前処理済みとし、
         片側2件以上の入力を勝手にsum/max/meanせず明示エラーにする
ビルダー出力（物理層・profile非依存）:
      debris_intrusion_left_m, debris_intrusion_right_m
      remaining_clear_width_m = max(W_clear − I_left − I_right, 0)
      official_closure（行政発表があれば）, hazard_data_status（沿道建物情報なし→UNKNOWN）
      variant（入力値を保持）, provenance.applied_constant_ids（実際に適用したregistry定数ID）
      共通4状態は後続integrationでここから派生し、M7 core v0.3は返さない:
      NARROWED＝「基準幅より狭いが残存幅>0」というprofile非依存の意味のみ。
      全通行者共通のCLOSEDは remaining=0 または official_closure のみ（E_minという未定義定数を作らない）
判定層（profile別・別モジュール）:
      remaining_clear_width_m と profile.required_width_m を比較して PASS/CONDITIONAL/FAIL。
      required_width v1=0.90m（伊DM236/1989・A1-NUM・参考レンジ。日本の円滑化基準A1化まで暫定）
      hazard_data_status=UNKNOWN → 判定もUNKNOWN（PASSに落とさない）
      WIDTH_REQ_WHEELCHAIR_MはM6専用であり、M7テスト・M7コアから取得しない
```

受け入れ条件：(a) 後続integrationでは出力スキーマに物理値列を追加しつつ既存4状態列も派生出力する。M7 core v0.3は物理mappingだけを返し、共通4状態のschema接続・派生は行わない。**実装セッションでは既存機能の非回帰と新規テスト全通過を確認**する。(b) **手計算フィクスチャは3ケース必須**（後退S=0が既定）：ケースA=幅4.0m・沿道h=7m・**片側のみ**倒壊(S=0)→remaining=max(4.0−3.27,0)=**0.73m**／ケースB=**両側**倒壊(S=0)→remaining=max(4.0−3.27−3.27,0)=**0m**／ケースC=片側倒壊・**後退S=2.0m**→I=max(3.27−2.0,0)=1.27→remaining=max(4.0−1.27,0)=**2.73m**。M7の期待値はprofile非依存の物理出力だけとする。(c) 生成物のヘッダに「Moya Eq.2/3は益城町木造建物のD>0回帰部分標本n=738。京町家への適用は設計仮定（TRANSFER=ADAPT）」を自動記載し、full sample母数は断定しない。(d) sensitivity_high_case⊆mean_caseの閉塞単調性テスト。(e) **M7 mutationテスト**：①片側の瓦礫項を削除②m↔cm③UNKNOWN→OPEN④mean+σ→mean−σ、の各変異でテストが必ず落ちることを確認して記録。`>=`／`>`はM7の`max(D−S,0)`では境界出力が同一のためM7必須mutationから外し、M6の`remaining_clear_width_m`対`required_width_m`境界テストへ移管する。

## 3-B データQAコード8種（自動検出・自動修正はしない）

Li et al. 2018の通り、半自動生成でも**手動QA/QCは不可避**（平均1.3h/mi²・A1）。検出→人間が現地/写真で確定、の分業にする。`python -m tools.qa data/` が `results/qa_report.csv`（code, severity, edge/node/poi_id, 説明, 検出幾何）を吐く。

| code | 検出条件 | severity |
|---|---|---|
| UNEXPECTED_DANGLE | 次数1ノードに行き止まりフラグなし | error |
| GEOMETRIC_CROSS_NO_NODE | edge同士が幾何交差するのに共有ノードなし | error |
| POI_WITHOUT_ENTRANCE | POIにentranceリンクなし（最近接edgeへの吸着だけ） | error |
| EDGE_CROSSES_BARRIER | edgeが障壁点/線レイヤーを跨ぐのに分割なし | error |
| PARALLEL_STAIRS_RAMP | 階段edgeの近傍に並行スロープ候補（両方登録すべき） | warn |
| HAZARD_BOUNDARY_UNSPLIT | edgeが警戒区域・浸水域境界を跨ぐのに分割なし | error |
| WIDTH_CHANGE_CANDIDATE | 幅属性が隣接区間で急変／障害物データと矛盾 | warn |
| PRIVATE_ACCESS_UNKNOWN | 寺社門・私有地通り抜けに開閉時間・可否が未登録 | warn |

受け入れ条件：(a) 各codeに1つずつ、わざと壊した3〜5ノードのフィクスチャがあり、検出できることをテストで固定。(b) 正常データ（同梱ダミー）で全code 0件。(c) qa_reportは現地調査の巡回リスト（タスク01）にそのまま使える列構成。(d) 自動修正は実装しない（提案列`suggested_fix`は可）。
