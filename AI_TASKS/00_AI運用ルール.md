# AI差配のハーネス：回し方のルール

このリポジトリは「AIにコードを書かせても壊れない」ように組んである。守るルールは5つだけ。

## 1. 受け入れ条件は常に `pytest`

AIへの依頼は必ず「`python -m pytest tests/ -q` が全部通ること」を受け入れ条件にする。
人間は全コードを逐行確認しない。ただし**数式・単位・状態遷移・安全境界と、それを固定するテスト**は必ず人間（またはブリーフ担当と別のAI）が確認する。テストが仕様である——だからテスト自体の誤りが最も危険（実例：残存幅の手計算例が「両側h=7m・片側倒壊」という誤読誘発表記だった。→ AI_TASKS/03のケースA/B両建てとmutationテストで対処）。

- `tests/test_tiny_allocation.py` … 手計算と厳密一致する極小ケース。配分ロジックの正しさ
- `tests/test_invariants.py` … どんなデータでも成立すべき性質（保存則・容量・flow≦nearest・R_start単調・厳格≦楽観）
- `tests/test_schemas.py` … データ契約。壊れた入力はloadで止まる

## 2. 1セッション＝1モジュール

AIセッションには `AI_TASKS/` の該当ブリーフ1枚と、関係するファイルだけを渡す。
全部を一度に書き換えさせない。ブリーフにない変更（リファクタ含む）は依頼しない。

## 3. 機能を足すときは、先にテストを足す

新機能（例：待ち行列、2境界ケース）は、まず期待する数値・性質をテストに書き、
AIには「このテストを通す実装」を頼む。テスト自体をAIに書かせた場合は、
**人間がテストだけをレビュー**する（実装は読まなくてよい）。

## 4. 決定性を壊さない

乱数・時刻・辞書順依存を持ち込まない。同じ入力→バイト単位で同じ出力。
`results/all_runs.json` の差分が出たら、それは仕様変更であり、コミットメッセージで説明する。

## 5. 配分エンジンは共有資産として凍結する

`src/allocate.py`は藤沢キットと共有の純関数エンジン。変更するときは**両キットのテストを両方通す**こと（手計算一致テストが仕様）。ハザード・データ契約の変更は京都側（model/graph/runner）だけで行う。

## 6. 実データに切り替えたら `--forbid-synthetic`

```
python -m src.runner data/ --forbid-synthetic
```

ダミーデータ（SYNTHETIC_PLACEHOLDER）が1行でも残っていれば停止する。
発表直前のビルドは必ずこのフラグで行う。

## 人間にしかできない確認（AIに任せないこと）

- 施設マスタが**現行の公式指定一覧**と一致していること（古い140棟一覧を使わない）
- 弁天橋・参道階段・主要入口周りのedge形状と接続（QGISで目視）
- 需要数値の出所と係数の妥当性
- 画面・スライドの文言が「安全表現テーブル」（改訂設計書§10）に従っていること
- 引用のA1/A2確認（原本PDFを開くのは人間または独立監査AI。翻訳DOCX・AI要約からのA1化は禁止）

## 7. 数値定数は4分類し、レジストリ経由で使う（v2.1）

`data/constants_registry.yaml`参照。コードに数値を直書きせず定数名で参照する。
- **EVIDENCE_PARAMETER**：論文・法令由来。`A1-NUM`/`A1-EQ`＋`TRANSFER_STATUS`（DIRECT/ADAPT/STRUCTURE_ONLY/PRESENTATION_ONLY）必須。コード投入前に**別AIの独立二重確認**（2026-08-29実施済み分はレジストリに記録。実効：停止回数77:25:2の誤りを68:25:2へ訂正）
- **DESIGN_ASSUMPTION**：チーム設定値（wayfinding 1.2・判断遅延60s・wet 0.6・evidence_policy_v0等）。README注記とセット
- **COMPUTATIONAL_CONSTANT**：許容誤差・換算係数。レジストリ不要
- **FIXTURE_VALUE**：テスト用合成値。レジストリ不要

## 8. モデル分担とA1権限（v2.1）

簡単=Sonnet／中等度=Opus／設計・統合=Fable。**SonnetはCATALOG_ONLY**（書誌・DOI・重複・ライセンスまで。数値・式のA1昇格は原本ページを開いたOpus/Fable/人間のみ）。Opusのコード利用候補（定数・式・閾値・移植可否）は別Opusが相互監査（1↔2、3↔4）。
