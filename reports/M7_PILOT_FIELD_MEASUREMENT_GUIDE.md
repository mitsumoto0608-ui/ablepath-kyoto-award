# M7 パイロット現地幅員測定ガイド（15エッジ）

## 1. 目的

- 本計画の目的は、**出典追跡可能な実エッジ（source-traceable real edge）に対する最初の実測値**を取得することである。
- 目的は **computed_count（計算済みエッジ数）を増やすことではない**。数値を埋めるために推定値を作ることは本計画の目的に反する。
- 対象は `inputs/staging/PLATEAU-BUILDING-EVIDENCE-V2/M7_BUILDING_SIDE_CANDIDATES.json` に列挙された 15 エッジ（kyoto_kiyomizu 5、kyoto_arashiyama 5、fujisawa_enoshima 5）。
- 本ガイドの時点では、幅員は 1 件も測定されていない。計画 CSV の `clear_width_static_m` は全行空欄であり、空欄は「未測定」を意味する。**欠測は 0 ではない。**

## 2. 用語定義

### 2.1 clear_width_static_m（静的有効幅員）

- 定義: 歩行可能有効幅員の**静的値**。固定障害物を除いた**最小有効幅**。
- 測定線の定義: 歩道端（縁石・側溝の歩行可能端）から、反対側の建物前面線または固定物までの**水平最短距離**。
- 測定位置ルール: 測定断面はエッジ進行方向に対して直交させ、地表面から高さ 1.0 m 前後の水平面で測る（庇・看板等の上空張り出しは `notes` に記録し、静的値には含めない）。
- この値は「その場に恒常的に存在する構造物」だけを反映する。人・自転車・仮設物によって一時的に狭くなっている状態を書き込んではならない。

### 2.2 remaining_clear_width_m（M7 出力）

- `schemas/hokonavi_2024_mapping.yaml` の `width_separation` に従い、静的値 `clear_width_static_m` と シナリオ値 `remaining_clear_width_m` は**別フィールド**であり、上書きは禁止（`overwrite_forbidden: true`）。
- `remaining_clear_width_m` は M7 の**出力**であり、`静的値 − 瓦礫等の侵入量` として計算で得られるものである。現地で書き込むフィールドではない。
- 現地で観測される一時的障害物（駐輪・露店等）は、フォームの `obstacle_type_temporary` / `obstacle_width_m_temporary` / `remaining_clear_width_m_observed` に**別々に**記録する。
- `remaining_clear_width_m_observed` は「訪問時点の観測値」であり、**M7 の出力ではない**。M7 の入力にも出力にも自動的には流れない。

## 3. 測点（station）ルール

- エッジの始点から 10 m 間隔で測点を置き、さらに**両端点を必ず測点とする**。最低 3 点。
- 測点 ID は始点側から `ST01`, `ST02`, … と連番。`station_offset_m` は始点からの沿線距離（m）。
- 測点座標は計画 CSV のジオメトリから事前に算出しておき、現地では ID と実距離で照合する。
- 断面ごとに左右両側（side=BOTH）を観測する。

## 4. エッジ代表値（controlling minimum）の決め方

- エッジの `clear_width_static_m` は、**全測点の静的有効幅員の最小値**とする。
- 最小値を与えた測点の `station_id` を必ず `notes` に記録する（例: `controlling_station=ST04`）。
- 測点間で明らかに狭い箇所を目視した場合は、追加測点を設けてよい（追加測点は `ST04a` 等とし、`notes` に追加理由を書く）。

## 5. 障害物の分類

- 固定（fixed）: 電柱、看板基礎、植栽枡、段差付き側溝、消火栓、擁壁、恒久的な柵。→ 静的値から**除外して**測る（すなわち静的値を狭める）。
- 一時（temporary）: 駐輪、置き看板、露店、工事仮設、荷捌き車両、ゴミ集積。→ 静的値には**反映しない**。別欄に記録する。
- 判断に迷う場合は「一時」として記録し、`notes` に判断理由と写真 ID を書く。推測で固定に格上げしない。

## 6. 左右の定義

- 左右は `from_node → to_node`（エッジのデジタイズ方向）に対する進行方向左右で定義する。計画 CSV の `start_node` / `end_node` がその方向である。
- PLATEAU 建物候補の左右も同一規約（`side_convention`）で列挙されている。現地の左右がこれと食い違うと感じた場合は、勝手に入れ替えず `notes` に記録する。

## 7. 写真プロトコル

- 各測点で最低 2 枚: (1) 進行方向（from→to）を向いた写真、(2) 測定断面を横から見た写真。
- 画角内に**スケールバー（またはメジャーを伸ばした状態）**を必ず入れる。
- ファイル名 = `<edge_id>_<station_id>_<direction>_<連番>`。`direction` は `FWD` / `BWD` / `SEC`（断面）。
- 写真 ID を `photo_ids` にセミコロン区切りで記録する。
- 私有地・店舗内部・人物が特定できる構図は避ける。

## 8. 機器と校正

- 主機器: レーザー距離計 class 2、公称精度 ±1.5 mm。予備として 5 m 鋼製巻尺。
- 表示分解能: 0.01 m。記録も 0.01 m 単位。
- 校正: 出発前に既知長（例: 2.000 m の基準尺）で 3 回確認し、`notes` に確認値を記録。
- レーザーが屋外照度で読めない場合は巻尺値を採用し、`instrument` 欄に実際に使った機器を書く。

## 9. 誤差予算（PROPOSAL）

- 機器誤差 ±0.002 m
- 測定断面の直交性・保持姿勢 ±0.02 m
- 歩道端／建物前面線の判定（エッジ定義の曖昧さ、植栽・凹凸の扱い） ±0.04 m
- 合成（二乗和平方根）で概ね **±0.05 m**。計画 CSV では `PROPOSAL` と明示している。実測後に実データで見直すこと。

## 10. DEM の扱い

- **DEM から段差（lev_diff）や横断勾配を導出してはならない。** 解像度と生成過程が歩行スケールの段差に対応していない。
- 段差・横断勾配は、必要になった時点で**独立した現地観測項目**として追加する。本計画はそれらを要求しない（フォームにも列を置かない）。

## 11. 安全・許可

- 対象は観光客の多い街路（三年坂・二年坂系、嵐山幹線沿い、江の島周辺）を含む。**早朝（開店前）に測定する**ことを原則とする。
- 車道内での測定・交通妨害は行わない。東大路通のような幹線沿いのエッジは歩道内から測る。
- 私有地に立ち入らない。建物前面線は公共空間側から観測する。
- 三脚等で通行を塞がない。人が接近したら測定を中断する。
- 事業者・自治体への事前連絡が必要と判断した場合は、測定前に人間の担当者へエスカレーションする。

## 12. データの取り回し

1. 現地フォーム（`reports/M7_PILOT_FIELD_FORM_TEMPLATE.csv` を印刷または端末入力）で測点単位に記録する。
2. 帰着後、同フォーマットの CSV（UTF-8 / LF / ヘッダ行あり / BOM なし）として保存する。
3. `inputs/staging/<TASK-ID>/` に CSV を置き、`source_manifest`（取得日時・観測者・機器・ファイルハッシュ）を同梱する。
4. 写真は **Dropbox に置き、Git に入れない**。`photo_ids` はマニフェスト経由で Dropbox 上のパスに解決できるようにする。

## 13. verification_status の流れ

`UNMEASURED` → `MEASURED` → `INDEPENDENTLY_CHECKED` → `ACCEPTED`

- `MEASURED`: 現地で 1 名が測定・記録した状態。
- `INDEPENDENTLY_CHECKED`: 別の観測者が少なくとも controlling station を再測し、差が誤差予算内であることを確認した状態。
- `ACCEPTED`: 人間のレビュアが受理した状態。

## 14. M7 入力にならないもの（人間の凍結が必要）

- `building_face_to_walkspace_boundary_m_left` / `_right`（S_observed）は、**セットバック判定が凍結されるまで M7 入力にしない**。現時点の候補列挙は `CANDIDATE_ENUMERATION_ONLY_SETBACK_NOT_FROZEN` である。
- `verification_status != ACCEPTED` の幅員は、いかなる場合も M7 入力にしない。
- `remaining_clear_width_m_observed` は観測記録であり、M7 出力 `remaining_clear_width_m` として書き出さない。

## 15. 禁止事項

- 道路種別（highway クラス）、車道幅員、写真のみからの幅員推定。
- 近傍エッジの値の流用、既定値・中央値の代入。
- 欠測を 0 や `OPEN` 等に読み替えること（`missing ≠ 0`）。
- 静的値欄に一時的障害物込みの値を書くこと。
- 検証済みでない街路名の記入（未検証の場合は中立記述のままにする）。
